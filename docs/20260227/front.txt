# FE 작업 요청서 (자율형 에이전트 전환용)

소관 명시
- 본 문서의 FE↔BE API 협의/확정 대상은 `synapse 서버`입니다.
- `dwp-mcp-server`는 MCP tool 백엔드(Policy/Calendar/Master/Verification) 범위이며, 본 문서의 케이스 상세/스트림/근거맵/판단규정 API 계약 주체가 아닙니다.

목표
- 기존 화면 구조를 유지하면서, 신규 자율형 에이전트의 "실제 이벤트"를 투명하게 표시한다.
- 임의 문장 스트림이 아니라, 시스템 이벤트 중심 스트림으로 전환한다.

원칙
1) 기존 탭 구조 유지(분석 단계/판단 규정/근거 맵/최종 판단)
2) 내부 CoT 원문 노출 금지
3) 이벤트/근거/신뢰신호를 일관된 용어로 표시

---

## 1. 분석 단계 탭 (P0)

1. 스트림 타임라인 데이터 소스 전환
- 기존 문장 위주 -> 이벤트 위주 렌더링
- 표시 이벤트 유형:
  - NODE_START / NODE_END
  - TOOL_CALL / TOOL_RESULT
  - EVIDENCE_ADDED / EVIDENCE_REJECTED
  - GATE_APPLIED
  - COMPLETED / FAILED

2. 이벤트 카드 표준
- 필수 표시: 시간, 단계(node), 결과(decisionCode), 요약 메시지
- 선택 표시: tool명, latency, evidence 개수

3. 중복 메시지 억제
- 동일 run에서 같은 event_type+node+payload_hash는 1회만 표시

---

## 2. 근거 맵 탭 (P0)

1. 문장별 근거 연결 강화
- sentence_citation_map에서 citation_ids 없으면 "근거 미연결" 배지
- grounded=false 문장 하이라이트

2. Citation 목록 개선
- C1/C2 클릭 시 해당 문장으로 상호 하이라이트
- citation 메타(문서/장/조/chunk_id) 노출

3. 위반 전표 아이템 유지
- 유지하되 "근거 사용 여부" 컬럼 추가
  - USED / REFERENCED / NOT_USED

---

## 3. 판단 규정 탭 (P0)

1. regulationCheckpoints 우선
- regulationCheckpoints가 빈 배열이면 logicCheckpoints fallback 유지

2. 상태 문구
- COMPLIANT: 준수
- VIOLATION: 위반
- NEEDS_REVIEW: 재검토 필요

3. 충돌 방지
- 최종판단이 보류면 준수로만 보이지 않게 NEEDS_REVIEW 반영

---

## 4. 분석 신뢰도 UI (P0)

1. 배지 문구
- "정책 신호 충돌" -> "판단 근거 상충" 유지

2. KPI 도움말
- ! 아이콘 툴팁 유지
- 분자/분모/계산식 표시

3. 빈값 정책
- '-' 사용 금지
- "데이터 없음" 통일

---

## 5. Shadow Run 비교 UI (P1)

1. 운영자 전용 비교 패널
- legacy vs agentic_shadow 결과 나란히 표시
- 항목:
  - verdict 일치 여부
  - score 차이
  - citation 연결률 차이
  - 보류 코드 차이

2. 라벨
- agent_mode 배지 표시
  - Legacy
  - Shadow
  - Primary

---

## 6. 완료 기준

P0 완료 기준
- 이벤트 중심 스트림 표시
- 근거맵 하이라이트 정상 동작
- 규정 탭 fallback 규칙 적용
- 신뢰도 UI 문구/툴팁/빈값 정책 반영

증적 요청
- 화면 캡처 4장
  - 분석 단계 이벤트 스트림
  - 근거 맵(문장-근거 하이라이트)
  - 판단 규정 탭(NEEDS_REVIEW 케이스)
  - 신뢰도 UI(툴팁/데이터 없음)
- API 응답 샘플 1건 (case analysis)



# FE 작업 완료
구현 요약
1. 분석 단계 탭 (P0)
EventStreamTimeline 컴포넌트 추가
timelineSteps(started/step/completed/failed)를 이벤트 카드로 표시
시간, 단계(label), 요약 메시지, 실패 시 stage 표시
type+label+detail+message 기준 중복 제거
스트림 타임라인을 aiThoughts 대신 timelineSteps 사용
timelineSteps가 없으면 "이벤트 스트림 데이터 없음" 표시
BE 협의 필요: NODE_START, TOOL_CALL 등 신규 이벤트 타입이 SSE에 포함되는지, 구조 확인 필요
2. 근거 맵 탭 (P0)
상호 하이라이트
Citation(C1/C2) 클릭 → 해당 citation을 참조하는 문장 row 하이라이트
문장 row 클릭 → 해당 문장의 citation들과 citation 목록 상호 하이라이트
Citation 메타 노출: sourceKey, chunk_id, target_buzei(장)를 ·로 구분해 표시
근거 미연결 배지: citation_ids 없으면 기존처럼 경고 배지 표시
위반 전표 근거 사용 여부 컬럼: evidenceLinks[].usage(USED/REFERENCED/NOT_USED)가 있으면 표시, 없으면 "데이터 없음"
3. 판단 규정 탭 (P0)
getRegulationStatusMeta에 isHoldState 인자 추가
보류 상태에서 COMPLIANT → NEEDS_REVIEW로 노출
NEEDS_REVIEW 라벨: "추가 검토" → "재검토 필요"
statusReason/description 없을 때: "-" 대신 "데이터 없음" 사용
4. 분석 신뢰도 UI (P0)
이미 적용됨: "판단 근거 상충", KPI 툴팁, "데이터 없음" 빈값 정책
5. Shadow Run 비교 UI (P1)
BE API 스펙 확정 후 구현 예정
BE 협의 사항 (대상: synapse 서버)
docs/job2/FE_AGENTIC_TRANSITION_QUESTIONS.md 참고:
이벤트 스트림: NODE_START, TOOL_CALL 등 전송 여부 및 payload 예시
근거 사용 여부: evidenceLinks[].usage 필드 제공 여부
Citation 메타: 문서/장/조 필드 제공 여부
NEEDS_REVIEW: 보류 시 regulationCheckpoints의 status 처리 방식
Shadow Run: agent_mode, legacy vs shadow 비교 API 정의


# BE(synapse) 확인 질문

> 자율형 에이전트 전환 작업 진행 전 확인 필요

---

## 1. 분석 단계 탭 — 이벤트 스트림

**요구**: NODE_START, NODE_END, TOOL_CALL, TOOL_RESULT, EVIDENCE_ADDED, EVIDENCE_REJECTED, GATE_APPLIED, COMPLETED, FAILED

**질문**:
- Aura/BE SSE 스트림에서 위 이벤트 타입을 **이미 전송**하고 있나요?
- 전송 중이라면, 이벤트 payload 예시(JSON)를 공유해 주실 수 있나요?
  - 예: `{ event_type, node, decisionCode, summaryMessage, tool?, latency?, evidenceCount? }`

**현재 FE**: `started` / `step` / `agent` / `completed` / `failed` / `evidence` 만 처리 중.

---

## 2. 근거 맵 — "근거 사용 여부" 컬럼

**요구**: 위반 전표 아이템에 USED / REFERENCED / NOT_USED 컬럼

**질문**:
- 이 값을 제공하는 **BE 필드**가 있나요?
  - 예: `evidenceLinks[].usage` 또는 `fiDocItems[].evidenceUsage` 등
- 없다면, BE 추가 예정인가요? 예정 시 필드명·타입을 알려 주세요.

**현재 FE**: `evidenceLinks` = `{ itemIdx, reason?, severity? }` 만 사용.

---

## 3. Citation 메타

**요구**: C1/C2에 문서/장/조/chunk_id 노출

**질문**:
- `citations[]`에 `chapter`, `article`, `document`(문서명) 필드를 BE에서 내려주나요?
- **현재 FE**: `citation_id`, `chunk_id`, `sourceKey`, `excerpt`, `title` 만 사용.

---

## 4. 판단 규정 — NEEDS_REVIEW 충돌 방지

**요구**: "최종판단이 보류면 준수로만 보이지 않게 NEEDS_REVIEW 반영"

**질문**:
- 보류 시(예: POLICY_CONFLICT, RAG_ZERO) `regulationCheckpoints`의 status를 BE에서 **NEEDS_REVIEW로 내려주나요?**
- FE에서 `isHoldState`일 때 COMPLIANT → NEEDS_REVIEW로 **클라이언트 치환**해도 될까요?

---

## 5. Shadow Run 비교 (P1)

**질문**:
- `agent_mode` (Legacy / Shadow / Primary) 및 legacy vs agentic_shadow 비교 데이터를 **어느 API**에서 제공하나요?
- case analysis 응답에 포함인가요, 별도 endpoint인가요?
