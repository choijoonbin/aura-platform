# Aura 청킹 아키텍처 (정확도 중심 발표본)

> 대상: PM, AI/RAG 엔지니어, 운영 담당자  
> 목적: "왜 청킹 품질이 정답률 핵심인지", "현재 무엇을 적용했는지", "다음 고도화 방향"을 명확히 설명

---

## 1. 왜 청킹이 핵심인가

RAG 성능은 모델보다 먼저 **청킹 품질**에서 결정된다.

- 청크 경계가 잘못되면: 검색은 맞아도 인용이 틀린다.
- 메타데이터가 약하면: 필터/재현/감사가 무너진다.
- 중복/노이즈가 많으면: Top-K가 오염된다.

즉, 청킹은 저장 전처리가 아니라 **판정 정확도의 1차 통제 레이어**다.

---

## 2. 현재 아키텍처 (End-to-End)

```text
문서 등록
 -> 텍스트 추출
 -> 문서 유형 판별
 -> 1차 청킹(구조/의미)
 -> 2차 세분화(하이브리드)
 -> 품질 게이트(실패 시 차단)
 -> 임베딩
 -> 저장/활성화
 -> 분석 단계 RAG 검색/인용
```

현재 원칙:
- 품질게이트 실패 시 "그대로 저장"하지 않음
- 문장-근거 연결을 위해 메타데이터 강제
- 멀티테넌트/문서 경계(doc_ids)로 검색 범위 제어

---

## 3. 문서 유형별 청킹 전략

### 3.1 규정형 문서 (HIERARCHICAL/REGULATION)

- `제N장/제N조/항/호` 경계 우선 파싱
- 상위 경로 정보를 청크에 주입 (location/path)
- 필요 시 조항 내부를 2차 세분화(parent-child 링크 유지)

효과:
- "어느 장/조/항에서 근거가 왔는지" 추적 가능
- 근거 맵/감사 리포트에서 설명력 강화

### 3.2 일반 문서 (SEQUENTIAL/GENERAL)

- 의미 단위 분할(semantic) + fallback split
- 너무 짧거나 제목-only 청크 제거
- 중복 청크 제거로 검색 오염 방지

효과:
- 일반 매뉴얼/가이드 문서도 검색 품질 안정화

---

## 4. 품질 게이트(현재 적용)

저장 전 검증 항목:

1. 필수 메타 누락 검사
- `regulation_article`, `location`, `doc_id`, `tenant_id`

2. 노이즈 제거
- 빈 청크, 헤더 쓰레기, UUID류 패턴 제거

3. 길이/정보량 검사
- 너무 짧은 제목-only 청크 제거

4. 중복 제거
- exact + near duplicate 제거

5. 검증 리포트 생성
- `article_coverage`, `noise_rate`, `duplicate_rate`, `short_chunk_rate`
- `quality_gate_passed` 및 상세 리포트 기록

---

## 5. 적용 전/후 비교 (발표용)

### 적용 전(문제)
- 조항 경계가 섞여 인용 근거 불명확
- 검색 결과는 있어도 문장-근거 매핑 약함
- 중복/노이즈 청크로 top-k 품질 편차 큼

### 적용 후(개선)
- 조항/위치 기반 근거 추적 가능
- 품질게이트 기반으로 저품질 적재 차단
- 근거맵, citation, 판정보류 게이트와 연동성 강화

주의:
- 정확도는 청킹만으로 100% 보장되지 않음
- MCP 사실컨텍스트/분석 게이트와 함께 운영해야 완성도 상승

---

## 6. 현재 완성도 평가

현시점 평가는 "기반 완성 + 운영 튜닝 단계"다.

- 아키텍처 완성도: 높음 (구조/게이트/메타/연계 경로 확보)
- 운영 완성도: 중상 (문서별 품질 편차/임계치 튜닝 필요)
- 엔터프라이즈 적합성: 확보 중 (품질리포트+게이트+추적성 갖춤)

---

## 7. 앞으로의 고도화 방향

### Phase A: 품질 기준 고정
- 문서 유형별 합격선 확정
- 실패 시 적재 차단 정책 운영 표준화

### Phase B: 검색 정합성 강화
- 질의 재작성기(코드값→의미어)
- rule-first prefilter + vector rerank 고도화
- 0건 시 재시도 정책 표준화

### Phase C: 평가 자동화
- 골든셋 리플레이 자동평가
- 배포/릴리즈 게이트 연동
- 문서별 품질 대시보드 상시 모니터링
